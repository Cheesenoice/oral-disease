The user reported approximately eleven hours of elapsed time and stopped both sessions. Authenticated Kaggle status now returns `CANCEL_ACKNOWLEDGED` for full version 3 of both notebooks. The archived accessible log replay showed GPU initialization but no visible epoch output; direct current-log retrieval after cancellation returned empty output. The local monitoring workflow stopped after a Kaggle API connection timeout at 2026-10-21T02:29:15Z. It had no automatic recovery from this network exception. Account quota after cancellation reported 22.33 GPU hours used and 7.67 remaining; this is account-wide usage.

Intended workload: four independent fine-tunes, seed 42: YOLOv8n/caries, YOLOv8n/gum, YOLO26n/caries and YOLO26n/gum. Version 3 used up to 100 epochs, patience 20, 640-pixel input and batch 32. Caries trains on 1,522 images and gum on 747; validation is separate and test is not used for model selection. Two task workers per notebook each use one GPU.

The full submission records estimated wall durations of 0.99 hours (E0) and 1.10 hours (E1), derived from three-epoch smoke throughput. Those estimates were informational only: the submitted notebooks allowed 39,600 seconds (11 hours) per worker and the Kaggle session timeout was 43,200 seconds (12 hours). There was no parent process no-progress watchdog. The worker checkpoint guard only acts at an epoch-save callback and cannot interrupt a stall before one. This was the operational configuration failure: a long hard limit existed without an effective stall limit. It does not establish exactly which process stalled.

Corrective protocol was published in private code dataset v10 and used with data v1: 30 epochs, patience 8, one-hour per-worker cap, individual 10-minute task-log no-progress watchdogs, and two-hour Kaggle session timeout. After the user authorized a rerun, v4 of both kernels completed on T4 x2 and all four worker outputs were collected. Actual workers stopped after 19–22 epochs; worker elapsed time ranged from 258 to 471 seconds. The concurrent sessions finished in about 14 minutes wall time, and account quota moved from 22.33h used to 22.66h used.
